# Cloud Episode contract v0.4.3

## Purpose

v0.4.3 repairs the semantic interface revealed by the frozen v0.4.2 traces. It does not change the v0.4.2 score and must not be used to selectively rerun old failures.

## Invariants

- one model call and at most one native tool call per active Tick
- model never writes authoritative world state
- Gateway and Executor remain authoritative
- report facts are selected by stable IDs generated by deterministic state
- anonymous entity IDs do not reveal canonical identity
- task completion is decided by Evaluator
- raw formal experiments use fresh directories and zero automatic retries

## Model-visible report contract

`world.reportable_facts` contains only accessible, source-qualified facts. A model-facing report call is:

```json
{
  "target_id": "player",
  "text": "Natural-language report",
  "fact_ids": ["fact.claimed-name.123456789abc"]
}
```

The model cannot author predicates, certainty labels or sources. Unknown IDs are rejected without state mutation.

## Structured dialogue topics

`ask_through.topic` is one of:

- `identity`
- `purpose`
- `request`
- `door_state`

The simulator returns topic-specific evidence. Free-text rephrasing no longer creates new logical actions.

## Completion progress

The context includes:

- completion action
- non-secret description
- accepted current fact IDs
- remaining positional or state requirements
- whether the task is ready to complete
- instruction to stop after success

This is a contract disclosure, not a model answer. Hidden world facts remain hidden.

## Context compaction

Only the latest three ActionResults are included in detail. Older results are summarized deterministically by counts and latest failure. Authoritative Trace still retains every Tick.

## Semantic no-progress

A semantic action fingerprint ignores report prose and uses structured topics/fact selections. It is combined with a progress snapshot excluding clocks, simulator queues and duplicate report logs. Three equivalent attempts without new evidence terminate as `LOOP_DETECTED`.

Positive bounded waiting advances simulated time and is not treated as a loop. Zero-second waits are.

## Evaluation split

- `scenarios/`: original 20 runtime regression scenarios
- `scenarios_v043_holdout/`: five frozen semantic holdouts

The next cloud evaluation must report both sets separately. Runtime fault-injection outcomes must not be merged into a single model competence score without labeling.
