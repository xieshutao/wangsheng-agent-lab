## 2. Root cause

The pre-fix `ActionLedger.records` retained every terminal `ActionRecord`.
`HeadlessGameWorld.gameplay_state()` serialized that entire collection as
`active_actions`. Repeated reports were also appended without a bound.
Consequently snapshots and saves grew with elapsed play time even though the
30-minute run remained behaviorally correct.

The previous accelerated action soak created a fresh world per lifecycle. That
avoided quadratic diff cost but also failed to test long-running live-state
bounds in one authoritative world.

## 3. Fix

The fix separates durable audit history from bounded live runtime state:

- only non-terminal actions remain in `active_records`;
- terminal actions move to a deterministic FIFO idempotency cache, default 256;
- the terminal cache is epoch-local and is not part of gameplay state or saves;
- load/reset creates a new epoch and clears the terminal cache, so old requests
  are rejected by epoch before they can mutate the restored world;
- request-response idempotency cache is FIFO-bounded, default 2048;
- recent report and heard-event histories are bounded, default 128 each;
- complete permanent history remains in the append-only JSONL trace;
- the accelerated soak now runs 10,000 action lifecycles in one
  `HeadlessGameWorld`, plus 10,000 scheduler events and 100 save/load cycles.

Clients must generate globally unique `message_id` and `action_id` values.
Idempotent replay is guaranteed inside the documented bounded cache window;
old-epoch traffic is always rejected after load/reset.

## 4. Deterministic gates

The post-fix deterministic acceptance must prove:

- full pytest suite passes;
- frozen Regression 20/20, v0.4.3 Holdout 5/5 and v0.5.1 Holdout 5/5;
- Golden Trace records and digest remain unchanged;
- bridge scenarios remain 20/20;
- one live world completes 10,000 actions;
- maximum active actions is at most one and final active actions is zero;
- terminal cache never exceeds its configured limit;
- request cache never exceeds its configured limit;
- report history never exceeds its configured limit;
- 100 save/load cycles preserve gameplay digest and clear epoch-local terminal
  cache;
- maximum deterministic save payload remains below 128 KiB.
