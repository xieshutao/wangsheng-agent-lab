# WangSheng v0.8 — Single-Room / Single-NPC / Three-Day Vertical Slice

## 1. Product question

This milestone answers one question only:

> Can one recorded memory, expressed through one NPC and one room, create a visible and understandable consequence on the next day?

The v0.7 Memory Versioning Kernel is frozen and authoritative. v0.8 does not reopen model capability work and does not permit an LLM to mutate world state.

## 2. Frozen scope

In scope:

- one front-hall greybox;
- one front door;
- one embodied NPC: Qingyan;
- one scripted visitor: Xiaoman;
- one paper crane evidence object;
- one three-day progression;
- one Night-1 record;
- one Day-2 visible consequence;
- one Day-3 identity decision;
- save/load and idempotent action IDs;
- local HTTP JSON bridge for UE.

Out of scope:

- additional NPCs;
- full hall or open world;
- voice, lip sync, face animation;
- local model retraining or a new model bake-off;
- free-form LLM world mutation;
- procedural rooms;
- final art, packaging, multiplayer, platform optimization.

## 3. Authority boundary

- UE owns physical execution, player input, collision, navigation, animation and visible presentation.
- v0.8 slice runtime owns progression, command availability, idempotency and save/load envelope.
- v0.7 MemoryVersioningKernel owns events, observations, memory versions, forgetting, records, acknowledgement, manifestation and replay digests.
- Any model backend may produce dialogue wording only after deterministic state is resolved.

## 4. Day structure

### Day 1

The player may collect three evidence families:

1. Xiaoman self-identifies at the door.
2. The paper crane has an old auditable connection to the hall.
3. Qingyan reports that she has no clear memory of the child.

At night, the player records exactly one supported candidate or records nothing.

### Day 2

The selected Night-1 record produces a deterministic manifestation. The player must be able to point to a visible difference without reading developer documentation.

### Day 3

The player may read the death archive, inspect body continuity and request Xiaoman's consent. The final deterministic outcomes are:

- old resident continuation;
- a new person using the name Xiaoman;
- name recognized while history remains unresolved;
- refusal to create a new connection.

No outcome deletes the prior death, the Day-1 knock or other canonical events.

## 5. UX rule

The player-facing notebook uses three layers:

1. memory fragment;
2. formal proposition;
3. evidence and risk details.

The first greybox may implement these as three panels; it must not expose raw Python objects as the final UX.

## 6. Exit gate

The milestone passes only when all are true:

- the canonical three-day path completes in a packaged or editor-playable UE build;
- Day-1 record visibly changes Day 2;
- each UE command uses a unique action_id and duplicate delivery is idempotent;
- save/load restores the same phase, choice and digest;
- invalid decisions are rejected with a reason_code;
- v0.7 tests remain green;
- no model call is required to complete the slice;
- a tester can answer: what I recorded, why the consequence happened, and what past fact was not changed.
