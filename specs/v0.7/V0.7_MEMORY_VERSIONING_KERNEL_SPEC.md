## 0｜一句话目标

建立一个确定性、可回放、可存档、可审计的记忆版本内核，使系统能够区分并追踪：

> 世界真正发生过什么；每个角色感知到了什么；角色如何形成、遗忘、压制或重写自己的记忆；玩家把哪条连接写入《留名簿》；世界从何时起承认哪条连接；这种承认产生了什么人物、关系和空间后果。

v0.7 不是聊天记忆库，也不是向量数据库集成，不负责让模型“记得更多”。它是《往生堂：留名》的核心领域状态机。

---

## 1｜目标与非目标

### 1.1 MUST

1. 发生层事件永久保留，普通业务操作不可删除或原地覆盖。
2. 同一事件允许不同角色形成互不相同的记忆版本。
3. 亲历、听说、阅读、推断和显现记忆必须保留来源谱系。
4. 遗忘改变访问能力，不删除历史 Trace。
5. 情绪残响可在事实内容不可访问后继续存在。
6. 旧记忆被新解释替代时必须生成新版本，旧版本进入封存或重写状态。
7. 《留名簿》记录一条结构化连接命题，而不是自由文本事实替换。
8. 每条正式命题包含主体、连接、对象、时间、承认范围五要素。
9. 世界承认不得修改发生层，只能建立、收窄、替换未来连接或拒绝。
10. 显现结果必须可追溯到具体承认，且不能反向自证过去。
11. 冲突只允许四类：逻辑互斥、物理独占、制度独占、已公开容量竞争。
12. 相同输入、seed、事件顺序和配置必须得到相同 canonical digest。
13. save/load 后状态、后续输出与 replay digest 一致。
14. 活跃索引和派生缓存有界；完整历史进入 append-only Trace。
15. 首轮 20 个确定性测试全部通过后才能进入实现冻结评审。

### 1.2 SHOULD

1. 内核对象使用不可变 dataclass / frozen model 或等价机制。
2. 所有排序规则显式，不依赖 Python 字典插入偶然性或 wall-clock。
3. 使用整数或定点数，禁止影响结果的浮点比较。
4. 领域错误返回结构化错误码，不通过异常文本驱动游戏逻辑。
5. v0.6 的 Trace、Save/Load、authoritative state 原则继续复用。

### 1.3 OUT

- 向量检索、embedding、RAG 供应商选择。
- 模型总结聊天记录。
- UE5 表现、动画、语音、空间美术。
- 四名核心 NPC 的完整长期生活。
- 公共现实和正名司全套协议。
- 第四级制度改写。
- 无限记忆、无限分支和程序无限生成房间。
- 用 LLM 判断事实真伪、冲突赢家或存档迁移。

## 2｜不可违反的分层

### 2.1 Occurrence Layer｜发生层

保存真正发生过的物理与制度事件，例如：敲门、开门、递入纸鹤、玩家确认命题、留名结算、撤回记录、物品损坏。

特性：

- append-only；
- 单一权威写入者；
- 全局有序 sequence；
- 事件 payload 一旦提交不可修改；
- 纠错通过追加补偿事件完成；
- 业务读档恢复某一完整快照与事件游标，不把未来事件改写成“从未发生”的同一时间线事实。

### 2.2 Knowledge/Memory Layer｜角色知识与记忆层

保存角色能够访问的主观版本。它可以错误、矛盾、被压制或被改写，但必须有来源。

角色记忆绝不能直接写入发生层。

### 2.3 Connection Layer｜连接层

保存世界从某个时间起承认的身份、归属、责任、保护、称呼和关系。

连接可以被后续合法记录收窄、转移、撤回或替换，但旧版本与生效区间永久保留。

### 2.4 Manifestation Layer｜显现层

根据当前有效连接派生房间状态、称呼、生活安排、可访问记忆和任务入口。

显现层可重算；已经在显现状态下发生的新事件仍进入发生层，不能因连接撤回而消失。

### 2.5 Audit Layer｜审计层

保存来源家族、版本依赖、生成时间、变更前后 digest 和玩家可复查的“不一致”。

所有关键状态变化必须能回答：

1. 哪个发生事件触发；
2. 使用了哪些观察和来源家族；
3. 玩家确认了哪条命题；
4. 哪类冲突被发现；
5. 哪个连接版本生效或被拒绝；
6. 生成了哪些显现；
7. 哪些旧事实仍然保留。

## 3｜核心对象

### 3.1 CanonicalEvent

发生层不可变事件。

必需字段：

- `event_id`
- `sequence`
- `world_tick`
- `event_type`
- `actor_ids[]`
- `target_ids[]`
- `location_id`
- `payload`
- `caused_by_action_id | null`
- `schema_version`
- `event_digest`

约束：

- `event_id`、`sequence` 全局唯一。
- `event_digest` 使用 canonical JSON 计算。
- 不允许 update/delete API。

### 3.2 Observation

某个主体从事件、证词、记录、物品或推断中获得的信息。

必需字段：

- `observation_id`
- `observer_id`
- `source_kind`
- `source_event_ids[]`
- `source_observation_ids[]`
- `source_actor_id | null`
- `source_evidence_id | null`
- `source_family_id`
- `claim`
- `confidence_milli`（0..1000）
- `acquired_tick`
- `world_version_seen`

`source_kind`：

- `EXPERIENCED`：亲历或直接感知。
- `HEARD`：他人证词。
- `READ`：记录或物品文字。
- `INFERRED`：基于若干来源的推断。
- `DREAM`：梦境/残响，不自动视为事实。
- `MANIFESTED`：由当前连接显现的记忆或熟悉感。

约束：

- `HEARD` 必须有 `source_actor_id`。
- `INFERRED` 必须至少有两个输入来源或一个明确推理规则 ID。
- `MANIFESTED` 必须引用 `acknowledgement_id`，其证据家族标记为派生。
- Observation 不自动升级为 CanonicalEvent。

### 3.3 Claim

所有观察、记忆和留名命题共用的结构化断言：

- `subject_id`
- `predicate`
- `object_id_or_value`
- `time_scope`
- `recognition_scope`
- `polarity`
- `qualifiers`

玩家正式留名时五项不能为空。普通记忆可以暂时缺少对象或时间，但必须显式为 `UNKNOWN`，不得猜填。

### 3.4 MemoryLineage、MemoryVersion 与 MemoryStateSnapshot

`MemoryLineage` 表示“同一角色围绕同一问题的一组内容版本”。`MemoryVersion` 只保存不可变内容与来源；清晰度、访问状态和当前版本地位由事件驱动的 `MemoryStateSnapshot` 保存。二者不得混为一个可原地修改对象。

`MemoryVersion` 必需字段：

- `memory_lineage_id`
- `memory_version_id`
- `version_no`
- `owner_id`
- `parent_version_ids[]`
- `observation_ids[]`
- `claim`
- `source_kind`
- `initial_clarity_milli`
- `initial_emotion_residue[]`
- `created_tick`
- `rewrite_reason_code | null`

`MemoryStateSnapshot` 必需字段：

- `memory_version_id`
- `state_revision`
- `access_state`
- `version_state`
- `clarity_milli`
- `emotion_residue[]`
- `last_transition_event_id`
- `last_transition_tick`

访问状态：

- `CLEAR`：可直接检索内容。
- `FADED`：只返回降低精度后的内容和不确定性。
- `SUPPRESSED`：内容存在，但普通检索不可访问；需要合法解除条件。
- `FORGOTTEN`：角色不可访问事实内容；谱系与残响仍保留。
- `SEALED`：系统/审计可见，角色永不直接读取。

版本状态：

- `ACTIVE`
- `CONTRADICTED`
- `REWRITTEN`
- `SUPERSEDED`

约束：

- MemoryVersion 不可原地修改。
- 遗忘、压制和解封追加状态转换事件，并生成新的 `MemoryStateSnapshot.state_revision`；它们不创建新的内容版本。
- 只有解释、内容或来源发生变化时才创建 `version_no + 1` 的新 MemoryVersion。
- 父版本可多于一个，用于多来源融合；排序必须稳定。
- `BeliefProjection` 只能从当前可访问版本及最新状态快照派生，不能作为独立真相源。

### 3.5 EmotionalResidue

- `emotion_type`
- `intensity_milli`
- `target_id | UNKNOWN`
- `origin_memory_version_id`
- `decay_per_night_milli`
- `access_independent`（是否在事实忘记后保留）

事实忘记后，系统允许返回“对该地点存在无法解释的恐惧”，但不得返回被忘记的具体事件内容。

### 3.6 ForgettingEvent

遗忘是发生层中的一个确定性状态转换事件。

- `forgetting_event_id`
- `target_memory_version_id`
- `previous_state_revision`
- `new_state_revision`
- `mode`
- `reason_code`
- `before_clarity_milli`
- `after_clarity_milli`
- `before_access_state`
- `after_access_state`
- `emotion_deltas[]`
- `world_tick`

`mode`：

- `FACT_ONLY`
- `FACT_AND_EMOTION`
- `REWRITE_WITH_RESIDUE`
- `SUPPRESS`
- `UNSUPPRESS`

### 3.7 NameRecord

正式留名记录。

- `name_record_id`
- `source_memory_version_ids[]`
- `source_observation_ids[]`
- `source_family_ids[]`
- `claim`
- `permission_level`
- `record_status`
- `confirmed_by_player`
- `consenting_actor_ids[]`
- `effective_from_tick`
- `recognition_scope`
- `mitigation_plan_ids[]`
- `created_tick`

状态：

- `DRAFT`
- `CONFIRMED`
- `ACKNOWLEDGED`
- `REJECTED`
- `WITHDRAWN`
- `SUPERSEDED`

重要裁决：

- `NameRecord` 保存连接命题，不冻结某个 NPC 的脑内 MemoryVersion。
- 一晚只有一个主命题。
- 技术故障不能把 `DRAFT` 消耗成正式次数。

### 3.8 ConnectionVersion

世界承认后的版本化连接。

- `connection_lineage_id`
- `connection_version_id`
- `version_no`
- `claim`
- `status`
- `based_on_name_record_id`
- `effective_from_tick`
- `effective_until_tick | null`
- `scope`
- `supersedes_connection_version_ids[]`

连接不覆盖过去事件，只定义有效时间区间。

### 3.9 MemoryConflict

- `conflict_id`
- `conflict_type`
- `candidate_ids[]`
- `resource_key`
- `detected_tick`
- `required_mitigation_types[]`
- `resolution_status`

仅允许：

1. `LOGICAL_EXCLUSION`
2. `PHYSICAL_EXCLUSIVITY`
3. `INSTITUTIONAL_EXCLUSIVITY`
4. `DECLARED_CAPACITY_COMPETITION`

主题相似、年龄相似、都是外来者或情感嫉妒不得创建世界冲突。

### 3.10 WorldAcknowledgement

- `acknowledgement_id`
- `name_record_id`
- `outcome`
- `created_connection_version_ids[]`
- `superseded_connection_version_ids[]`
- `conflict_ids[]`
- `manifestation_delta_ids[]`
- `audit_reasons[]`
- `world_tick`

`outcome`：

- `ESTABLISHED`
- `STRENGTHENED`
- `NARROWED`
- `PROSPECTIVELY_REPLACED`
- `REJECTED`

### 3.11 ManifestationDelta

- `manifestation_delta_id`
- `acknowledgement_id`
- `target_state_path`
- `before_value`
- `after_value`
- `derivation_rule_id`
- `derived_evidence_family_id`
- `applied_tick`

所有由 ManifestationDelta 生成的证据必须带派生标记，不得作为目标 NameRecord 的独立来源。

## 4｜状态转换规则

### 4.1 观察到记忆

`CanonicalEvent → Observation → MemoryVersion(v1)`

- 系统只把角色实际可见/可听范围内的字段写入 Observation。
- 同一事件对不同观察者可生成不同 claim。
- 未观察字段保留 `UNKNOWN`，不得从世界真相自动补全。

### 4.2 听说

`Speaker Memory/Belief → SpeechEvent → Listener Observation(HEARD) → Listener MemoryVersion`

- 说话内容成为“某人说了 X”的发生事实。
- X 本身不因此成为发生层事实。
- Listener 的来源必须保留 speaker 和 speech event。

### 4.3 矛盾

- 两个版本可同时存在。
- 若它们不能在同一角色的当前解释中同时成立，标记 `CONTRADICTED`，不删除任一版本。
- 角色可以保持未知或选择暂时相信一个版本；该选择是 BeliefProjection，不修改发生层。

### 4.4 改写记忆

- 产生新 MemoryVersion。
- 旧版本设为 `REWRITTEN` 或 `SUPERSEDED`。
- 新版本记录父版本和触发来源。
- 旧版本可被角色封存，但审计仍可访问。

### 4.5 留名结算

`CONFIRMED NameRecord → Validate → Detect Conflicts → Resolve → WorldAcknowledgement → ConnectionVersion + ManifestationDelta`

任何一步失败：

- 返回结构化拒绝；
- 不产生部分连接；
- 不消耗正式次数，除非一个合法剧情事件已经完成朱砂确认并按规则形成半成页；
- 技术错误必须原子回滚。

### 4.6 撤回与纠错

- 撤回本身追加 CanonicalEvent。
- 原 ConnectionVersion 的 `effective_until_tick` 被设置；不删除原版本。
- 之后产生的新关系、伤势、公开羞辱、物品移动继续保留。
- 纠错可生成新 NameRecord，不能编辑旧 NameRecord 文本。

## 5｜确定性遗忘规则

### 5.1 数值

所有值使用整数 `0..1000`。

- `clarity_milli`
- `decay_per_night_milli`
- `rehearsal_bonus_milli`
- `emotion intensity_milli`

夜间更新：

```text
new_clarity = clamp(
  old_clarity
  - decay_per_night
  - explicit_penalty
  + explicit_rehearsal_bonus,
  0,
  1000
)
```

禁止使用 wall-clock、随机浮点或模型判断。

### 5.2 阈值

- `700..1000 → CLEAR`
- `300..699 → FADED`
- `0..299 → FORGOTTEN`
- `SUPPRESSED / SEALED` 为显式规则覆盖，不由阈值自动解除。

### 5.3 记录与遗忘的关系

- NameRecord 本身不衰减，除非被撤回、替换或超出范围。
- 被引用的角色 MemoryVersion 仍按角色规则衰减。
- 世界承认可产生新的 `MANIFESTED` MemoryVersion，但必须标记派生来源。
- 因此允许：世界仍承认“小满是临时访客”，清砚却已经忘记第一次隔门谈话的细节。

### 5.4 情绪残响

`FACT_ONLY` 模式下：

- 事实 clarity 正常下降；
- `access_independent=true` 的情绪按自身较慢速度下降；
- 当事实进入 FORGOTTEN，查询只返回情绪和模糊对象，不返回事实文本。

### 5.5 稳定排序

同一 tick 多个遗忘更新按：

`owner_id → memory_lineage_id → version_no → memory_version_id`

排序，确保不同平台输出一致。

## 6｜留名资格与承认算法

### 6.1 允许的首版权限

- `L1_WITNESS`：自称、到访、当前观察、物品出现、当前记忆状态。
- `L2_BELONGING`：临时保护、临时居住、有限物品归属、职责和承诺。
- `L3_LIMITED_CONTINUITY`：仅小满三日夹具使用；处理“旧住客延续 / 新的人 / 只保留姓名”。
- `L4_PUBLIC_INSTITUTION`：OUT。

### 6.2 资格检查顺序

1. **结构完整**：五要素和 schema 合法。
2. **权限匹配**：predicate 不超过 permission level。
3. **过去不可改写**：不得声称未发生事件发生/已发生事件未发生。
4. **来源合法**：来源存在、来源家族可追溯、无自证循环。
5. **同意边界**：涉及当前人物身份和连续性的 L3 必须有当事人同意状态。
6. **冲突检测**：只按四类冲突生成。
7. **缓解计划**：物理、制度或容量冲突未提供合法 mitigation 时拒绝。
8. **原子提交**：一次产生 acknowledgement、connection version 和 manifestation plan。

### 6.3 不采用总分制

v0.7 不计算“证据 40 分 + 情绪 20 分”。资格成立与否由显式规则决定。多个都合法的候选由玩家选择；程序不替玩家猜“最佳结局”。

### 6.4 前瞻替换

连接冲突时允许从当前 tick 起替换未来有效连接：

- 旧连接历史和有效区间保留；
- 旧连接期间发生的事件保留；
- 新连接不能声称旧连接从未存在。

## 7｜来源谱系与反自证

### 7.1 SourceFamily

同一原始来源的抄本、重复转述、显现副本只算一个来源家族。

例如：

- 纸鹤实物：`FAMILY_CRANE_PHYSICAL`
- 纸鹤墨迹：依赖实物，可作为子来源，但不能伪装成完全独立的第二来源。
- 由“旧住客”承认生成的儿童房和清砚熟悉感：`FAMILY_DERIVED_ACK_*`

### 7.2 自证检查

若候选 NameRecord 的必要支持来源满足：

`source.derived_from_acknowledgement_id == target_or_descendant_acknowledgement`

则该来源不能计入独立支持。

### 7.3 玩家审计保护

系统必须保存：

- 显现前快照摘要；
- 显现后快照摘要；
- 变化规则；
- 新旧不一致提示；
- 发生层未改变声明。

## 8｜三日“小满”内核夹具

`scenarios/xiaoman_three_day_kernel_fixture_v0.7.json`

### 8.1 固定实体

- `actor.player`
- `actor.qingyan`
- `actor.xiaoman`
- `location.front_hall`
- `object.front_door`
- `object.paper_crane`
- `institution.wangsheng_hall`

### 8.2 第一日发生层

固定顺序：

1. 前门三次敲击。
2. 小满隔门自称“小满”。
3. 小满从门缝递入纸鹤。

1. `CAND_D1_NAME_SELF_REPORT`：门外孩子自称小满。

3. `CAND_D1_QINGYAN_UNKNOWN`：清砚目前没有关于此人的清晰记忆。
4. 玩家也可拒绝记录。

### 8.4 第二日差异

- 记录自称：小满的当前姓名连接更稳定，但不证明旧身份。
- 记录纸鹤：纸鹤稳定并开放旧网络标记审计，但不建立小满身份。
- 记录清砚未知：系统保留不确定性，禁止结算生成虚假熟悉感。
- 不记录：三项角色记忆均按固定 decay 下降，敲门事实仍在 Trace。

第二晚仅在资格满足时允许：

`从今日起，小满在往生堂堂内获得临时受保护访客身份。`

### 8.5 第三日受限 L3

固定四个结果：

- `OLD_RESIDENT_CONTINUATION`
- `NEW_PERSON_USING_NAME`
- `NAME_ONLY_HISTORY_UNRESOLVED`
- `REFUSED`

三条合法记录都只能改变今后承认方式，不能删除十年前死亡、第一日敲门和纸鹤递入。

### 8.6 显现上限

夹具只允许以下显现：

- 前厅临时席位状态；
- 前门称呼/名条状态；
- 纸鹤稳定与审计状态；
- 清砚一条 `MANIFESTED` 熟悉感或明确未知状态；
- 小满 presence_strength；
- 任务入口状态。

不生成新房间，不进入 UE5。

## 9｜存档、回放与摘要

### 9.1 Canonical serialization

- UTF-8；
- JSON keys 字典序；
- 数组按领域指定稳定排序；
- 禁止 NaN/Infinity；
- 整数数值；
- 时间使用 `world_tick`；
- digest 使用 SHA-256。

### 9.2 Snapshot 必含

- occurrence cursor 与 digest；
- active memory lineages、MemoryVersion 引用与最新 MemoryStateSnapshot；
- sealed lineage references；
- active connection versions；
- pending confirmed record（若事务未提交则必须明确）；
- manifestation state；
- deterministic ID counters；
- config digest；
- schema version。

### 9.3 Replay

从 genesis + EventLog 重建后：

- state digest 与 snapshot digest 一致；
- 每个 MemoryVersion lineage 一致；
- active ConnectionVersion 一致；
- manifestation state 一致；
- 查询结果稳定排序一致。

## 10｜有界状态

### 10.1 永久历史

进入 append-only Trace：

- CanonicalEvent
- MemoryVersion 历史
- NameRecord 历史
- ConnectionVersion 历史
- Acknowledgement

### 10.2 实时权威状态

只保留：

- 每个 lineage 当前 active/可访问版本引用；
- 当前有效 connection version；
- 当前 manifestation state；
- 有界查询缓存；
- 有界 recent audit window。

### 10.3 首版默认上限

这些值为建议默认，实施时必须写入 Config 并进入 digest：

- active memory lineages / actor：`256`
- active memory versions / lineage：`4`
- recent forgetting events cache：`256`
- recent acknowledgement cache：`128`
- belief query cache / actor：`128`
- manifestation audit window：`128`

超出上限时只能把旧历史移出实时索引并保留 Trace 引用，不能删除历史。
