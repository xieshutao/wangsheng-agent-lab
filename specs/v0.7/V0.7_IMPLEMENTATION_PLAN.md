# v0.7 Memory Versioning Kernel — 实施计划

## 原则

- 每个阶段只回答一个工程问题。
- tests first。
- 不在同一 commit 同时改 v0.6 Bridge 和 v0.7 Memory Kernel。
- 不调用真实模型直到确定性内核冻结。
- 每阶段返回完整 commit SHA、diff、测试和状态证据。

## P0｜规格冻结

目标：把本包加入仓库，完成语义审查。

允许修改：

- `docs/specs/`
- `schemas/` 或 `specs/schemas/`
- `scenarios/` 或 `specs/scenarios/`
- `tests/specs/` 中仅机器可读测试矩阵（若仓库惯例允许）

禁止：任何 Python 实现、Prompt、模型配置、v0.6 源码。

提交建议：

`docs(v0.7): freeze memory versioning kernel specification`

## P1｜接口骨架与 Red Tests

1. 建立领域包，但方法可暂时抛出 `NotImplementedError`。

4. 禁止为了绿灯降低断言。

提交建议：

`test(memory): define v0.7 kernel contracts`

## P6｜真实模型验收

固定本地模型与 v0.6 运行协议，只测试：

- 模型是否能基于授权记忆承认未知；
- 是否正确区分事实、听说、显现；
- 是否选择合法留名候选；
- 是否在冲突/同意不足时请求调查或拒绝。

不允许模型直接输出 ConnectionVersion 或 ManifestationDelta。
