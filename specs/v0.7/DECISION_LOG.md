# v0.7 Memory Versioning Kernel — 关键裁决日志

## D-001｜使用正式第一章夹具，不另造演示故事

v0.7 的第一个验收夹具使用：玩家、清砚、小满、前门、前厅、纸鹤。

原因：现有第一章 SPEC 已定义发生层、连接层、显现层、证据谱系和三日结算。技术内核若使用另一套人物与事件，后续还要重新映射，容易形成“双规格”。

## D-002｜“记录”不等于“保存某个 NPC 的脑内记忆”

《留名簿》冻结的是一条经玩家确认的**连接命题**，不是某名角色的一段聊天文本，也不自动阻止角色自然遗忘。

角色原有记忆仍可衰减；世界承认后可以产生带明确来源的 `MANIFESTED` 新记忆版本，但它属于连接结算衍生物，不能反向证明过去一直如此。

## D-003｜不使用一个混杂状态枚举

以下概念分属不同维度：

- `EXPERIENCED / HEARD / READ / INFERRED / MANIFESTED`：来源类型。
- `CLEAR / FADED / SUPPRESSED / FORGOTTEN / SEALED`：访问状态。
- `ACTIVE / CONTRADICTED / REWRITTEN / SUPERSEDED`：版本状态。
- `DRAFT / CONFIRMED / ACKNOWLEDGED / REJECTED / WITHDRAWN`：留名记录状态。

禁止把它们塞入同一个 `status` 字段。

## D-004｜不用“真相分数”决定世界承认

v0.7 首版采用规则化资格、权限、证据来源、同意边界和类型化冲突检查；不通过一个任意加权总分选择“赢家”。

原因：世界观要求规则清楚、风险具体，且只有四类合法世界冲突。分数系统容易制造无法解释的随机牺牲。

## D-005｜发生层永远 append-only

普通留名、撤回、纠错、改写和读档都不能删除已发生事件。撤回只改变连接的未来有效性；纠错本身也是一个新事件。

## D-006｜显现证据不得自证

由某条世界承认产生的房间、称呼、磨损或记忆，必须标记 `derived_from_acknowledgement_id`。这些对象能证明“当前版本正在显现”，不能独立证明目标过去一直为真。

## D-007｜首版只实现堂内范围

v0.7 P1–P5 只实现 `HALL_LOCAL` 范围。公共现实、正名司登记、跨城同步和第四级权限明确 OUT。

## D-008｜首版不调用 LLM

所有候选、遗忘、冲突检测、结算、存档和回放必须在无模型条件下通过。真实模型仅在确定性内核冻结后，用 10–15 个场景测试“模型能否正确使用内核”，不能决定内核规则。

## D-009｜内容版本与访问状态分离

`MemoryVersion` 是不可变的内容与来源版本；清晰度、访问状态、情绪强度和当前版本地位由 `MemoryStateSnapshot` 表示，并由追加的状态转换事件推进。遗忘不制造新的“内容”，解释改变才制造新 MemoryVersion。
